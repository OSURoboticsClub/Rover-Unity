# Unity UDP Ros Bridge
 
 This documentation was generated by a human brain and may contain errors.

 There are 4 main ROS nodes that handle communication. Each receives JSON over UDP and converts it into the corresponding ROS function

- `udp_bridge_pub`: publishes the recieved data onto a ROS topic
- `udp_bridge_sub`: subscribes to a ROS topic, and sends results back to Unity over UDP
- `udp_bridge_srv`: sends a ROS service request and sends the response back to Unity over UDP
- `udp_bridge_action`: send a ROS action request, and sends the feedback and results to Unity over (you'll never guess) UDP.

A launch script called `startBridges.sh` exists to launch all of the bridges at once.

## Ports

Each bridge implmentation uses different UDP ports on localhost (`127.0.0.1`)

- `65434`: input for `udp_bridge_pub` (Unity to ROS)
- `65435`: output for `udp_bridge_sub` (ROS to Unity)
- `65436`: input for `udp_bridge_sub` configuration (Unity to ROS)
- `65437`: input for `udp_bridge_srv` (Unity to ROS)
- `65438`: output for `udp_bridge_srv` (ROS to Unity)
- `65439`: input for `udp_bridge_action`. (Unity to ROS)
- `65440`: output for `udp_bridge_action`. (ROS to Unity)

The port specifics are usually not of anyones concern, I mention them for the poor soul who has to maintain or expand this code.

## Publishing!

`PublishMessage(string message)` is the function you want to use when publishing. The function takes in a string containing JSON and sends it down to ROS for `udp_bridge_pub` to break down and handle. Publishers are created lazily the first time the bridge sees a topic.

JSON should be in the following format:

```json
{
  "topic": "/chatter",
  "msgType": "std_msgs/msg/String",
  "data": {
    "data": "Are you from Tennesse? Cause you're the only 10 I see!"
  }
}
```

Note that `msgType` must be a ROS interface type string

## Subscribe (and hit like!)

`ConfigureSubscription(string topic, string msgType)` is the function to use. It takes in two strings, the topic and the message type. No JSON is required when creating a subscription.

Whenever new information is published to the topic, `udp_bridge_sub` will serialize it into JSON and send it to Unity. `GetLatestMessage(string topic)` will return the latest message for the specified topic. The JSON will be in the following format.

```json
{
  "topic": "/chatter",
  "msgType": "std_msgs/msg/String",
  "data": {
    "data": "If a fat man puts you in a bag at night, don't worry! I told Santa I wanted you for Christmas."
  }
}
```

Again you will never write this JSON, it will be given to you by ROS.

## Services!

`PublishClientReq(string message, string serviceKey)` is one of two ways you make requests to ROS services. `message` is a string containing JSON in the below format. The `serviceKey` field is optional, and will be set to the service field of `message` if not supplied. `PublishClientReq` will wait for the service response and then return it, waiting a maximum of 0.5 seconds before timing out. 

`SendClientReq(string message)` is the other way to make requests to a ROS service. It takes in a string containing JSON in the below format and sends it to `udp_bridge_srv`. It will not wait for the response.

```json
{
  "service": "/set_bool",
  "srvType": "std_srvs/srv/SetBool",
  "request": {
    "data": true
  }
}
```

If you used `PublishClientReq`, the JSON sent back by `udp_bridge_srv` will be returned to you. If you used `SendClientReq`, then you must use `GetLatestServiceResponse(string serviceKey)`, where the `service_key` is the name of the service (the `service` field of the JSON). The response is in the following format

```json
{
  "service": "/set_bool",
  "response": {
    "success": true,
    "message": "I've got skittles in my mouth, wanna taste the rainbow?"
  }
}
```

## Lights! Camera! That last thing!

`PublishActionReq(string message, string actionName)` is the function for making an action request. It's very similar to `PublishClientReq` but it doesn't return the result (because actions have multiple responses). The `message` is a string containing JSON in the below format, `actionName` is an optional field that will be set to the `action` field of the JSON if not supplied.

```json
{
  "action": "fibonacho",
  "actionType": "action/IWantFibonachos",
  "request": {
    "amount": 6
  }
}
```

To get the latest feedback and/or results of the action, use the `GetLatestActionFeedback(string actionName)` function. `actionName` is the same as the `action` field of the request JSON. It will return JSON in one of the two following formats.

```json
{
  "action": "fibonacci",
  "feedback": {
    "_partial_sequence": [1, 1, 2]
  }
}
```

```json
{
  "action": "fibonacho",
  "result": {
    "_sequence": [1, 1, 2, 3, 5, 8],
    "_meaning_of_life": 42
  }
}
```
